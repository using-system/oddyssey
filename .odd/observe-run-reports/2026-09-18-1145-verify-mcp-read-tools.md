## 6. Decisions the spec must settle

1. **Whether this lineage's pass criteria become ratio-based (F12).** Two of its three absolute bands failed on a host change with byte-identical code. The spec must say whether the lineage keeps absolute ms (and therefore requires a host-state statement per run, with replays compared only across matching states) or adopts the yardstick ratios of section 4, item 1.
2. **Which deployment shape the read-tools bar rules on.** Unchanged from the baseline and still open: F9 costs per process start and nothing per request — a net loss for the one-shot driver this lineage measures, a net gain for the long-lived session server the package installs. The spec must say whether the bar is the request path alone (met with room: 47 ≤ 75 ms) or the one-shot client wall.
3. **Whether the merged inspect may be formatted (F11).** Declined in the ledger; this run measured the formatted form at 36–71 ms on the same host, which supports the ruling. The spec should record the measurement where the next reader of a 36.8 ms inspect — 78 % of the call — will find it, since the question will be asked again.
4. **Whether the lifecycle spans should carry the import/setup breakdown** (section 4, item 4) — a cost on every process start of ~0 ms but a change to the span shape check 12 keys on.
5. **Whether a docker span must name its call site** (section 4, item 5): two paths share one span name, and that ambiguity has already produced one wrong explanation in this lineage's own history.
6. **Whether the `#83` re-read branch must be observable** (section 4, item 6) — the digest half is filled, the branch half is not.
