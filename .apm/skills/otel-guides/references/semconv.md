# OpenTelemetry Semantic Conventions

Official docs root: https://opentelemetry.io/docs/specs/semconv/
Links ending in `index.md` return the page as raw markdown; fetch the page for the domain you are naming things in instead of recalling attribute names from memory.

| Section | What it covers | What to do with it |
| --- | --- | --- |
| [General](https://opentelemetry.io/docs/specs/semconv/general/index.md) | General conventions for spans, metrics, logs and events: general attributes, attribute and metric requirement levels, [naming](https://opentelemetry.io/docs/specs/semconv/general/naming/index.md), trace/metrics/logs/events/profiles conventions, recording errors, sessions. | Read before naming anything; the naming page is the rule set for any span, metric, or attribute name no existing convention covers. |
| [Resource](https://opentelemetry.io/docs/specs/semconv/resource/index.md) | Standard resource attributes and the sub-pages defining them: service (`service.name` Required/Stable, `service.version`, `service.namespace`, `service.instance.id`), deployment environment, container, host, Kubernetes, process and process runtime, cloud, FaaS, browser, device, OS. | Build the per-service resource block from here — `service.name` plus `service.version` and `deployment.environment.name` — and add the container/k8s/cloud attributes matching where the service actually runs. |
| [HTTP](https://opentelemetry.io/docs/specs/semconv/http/index.md) | HTTP client and server conventions, split into HTTP spans, HTTP metrics, and HTTP exceptions; status Mixed. | Use for every HTTP-facing service; instrumentations predating v1.20.0 of the document need the `OTEL_SEMCONV_STABILITY_OPT_IN` value `http` (or `http/dup` for a phased rollout) to emit the stable conventions. |
| [Database](https://opentelemetry.io/docs/specs/semconv/db/index.md) | Database client spans, metrics, and exceptions, plus per-system pages (SQL, PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, MongoDB, Redis, Cassandra, Elasticsearch, DynamoDB, Cosmos DB, CouchDB, HBase); status Mixed. | Use when planning DB client instrumentation; instrumentations predating v1.24.0 of the document need `OTEL_SEMCONV_STABILITY_OPT_IN=database` (or `database/dup`), and the per-system page is what pins system-specific attributes. |
| [Messaging](https://opentelemetry.io/docs/specs/semconv/messaging/index.md) | Messaging spans, metrics, and exceptions, plus per-system pages (Kafka, RabbitMQ, RocketMQ, AWS SQS, AWS SNS, Azure messaging, Google Cloud Pub/Sub); status Development. | Use for producer/consumer instrumentation and for deciding how a broker hop is represented; the migration switch is `OTEL_SEMCONV_STABILITY_OPT_IN=messaging` (or `messaging/dup`). |
| [RPC](https://opentelemetry.io/docs/specs/semconv/rpc/index.md) | RPC spans, metrics, and exceptions, plus gRPC, Connect RPC, Apache Dubbo, and JSON-RPC pages; status Release Candidate. | Use for gRPC/RPC service boundaries instead of bending the HTTP conventions; the migration switch is `OTEL_SEMCONV_STABILITY_OPT_IN=rpc` (or `rpc/dup`). |
| [Exceptions](https://opentelemetry.io/docs/specs/semconv/exceptions/index.md) | Exception conventions, split into exceptions on spans (deprecated) and exceptions in logs; status Stable. | Plan error recording as logs, not span events; instrumentations still emitting span events expose `OTEL_SEMCONV_EXCEPTION_SIGNAL_OPT_IN` with `logs` or `logs/dup`. |
| [FaaS](https://opentelemetry.io/docs/specs/semconv/faas/index.md) | Function-as-a-Service spans, metrics, and exceptions, plus an AWS Lambda page; status Development. | Use for serverless functions, whose invocation model does not fit the long-running-service conventions. |
| [Browser](https://opentelemetry.io/docs/specs/semconv/browser/index.md) | Browser conventions, currently defined for events only; status Development. | Use when a browser/SPA frontend is in scope, and treat the naming as unsettled in the plan. |
| [Mobile](https://opentelemetry.io/docs/specs/semconv/mobile/index.md) | Mobile platform conventions, currently defined for mobile events in logs; status Development. | Use when a mobile client is in scope, with the same caveat as browser: conventions are still in development. |
| [Runtime environment](https://opentelemetry.io/docs/specs/semconv/runtime/index.md) | Runtime environment metrics; status Development. Deliberately defines no standard top-level runtime instruments — runtime metrics are namespaced per environment (`jvm.*`, `cpython.*`, ...). | Use to check what a language runtime's metrics are called before promising "runtime metrics" in a plan; the names come from the runtime namespace, not a shared instrument set. |
| [System](https://opentelemetry.io/docs/specs/semconv/system/index.md) | System-level metric conventions: system, container, Kubernetes, OpenShift, OS process, and hardware metrics; status Development. | Use when the plan collects host/container/pod metrics alongside application telemetry. |
| [Registry](https://opentelemetry.io/docs/specs/semconv/registry/index.md) | Automatically generated registry of every defined attribute and entity. | Use to look up whether an attribute name already exists (and its exact spelling and stability) before inventing one. |

## Planning notes

- The docs root reports the semantic conventions version it renders (1.44.0 at the time of writing) — read the version and the per-page status badge (Stable / Release Candidate / Development / Mixed) from the fetched page rather than assuming a name is frozen.
- `OTEL_SEMCONV_STABILITY_OPT_IN` is the documented migration switch shared by HTTP, database, messaging, and RPC: `<area>` emits the stable conventions, `<area>/dup` emits both for a phased rollout, and the default is whatever the instrumentation emitted before. Name the value explicitly in the plan whenever existing instrumentation predates the stable conventions.
- When stored observation reports exist, prefer `<area>/dup` over the bare `<area>`: the bare value *replaces* the legacy instruments, invalidating every stored before-value, while `/dup` emits both families side by side (measured on `opentelemetry-instrumentation-httpx` 0.65b0: the default mode puts no peer attribute at all on `http.client.duration`, and `http/dup` added the stable instruments agreeing with the legacy ones to within 0.3 ms).
- For an outbound call to produce a *service-graph* edge, name the peer with `peer.service` alongside `server.address`: Tempo's metrics-generator builds uninstrumented-peer nodes from its `peer_attributes` default (`peer.service`, `db.name`, `db.system`) — the otel-lgtm image ships that default — so `server.address` alone yields a correct span and no edge (measured: `traces_service_graph_request_total` stayed empty until `peer.service` was added).
- Domain conventions are split per signal (spans / metrics / exceptions or logs) — fetching only the domain index is not enough; open the signal page the plan actually names things in.
- Generative AI conventions are no longer part of this document set; the index redirects them to a separate `semantic-conventions-genai` repository.
- Conventions exist for the environment as well as the code (resource, system, runtime) — a plan that names only spans and metrics leaves the resource attributes, which everything is correlated by, unspecified.
